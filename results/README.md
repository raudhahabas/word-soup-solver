# Results

Raw data behind the report. Every player was run on the **same 100 random 12×9 grids** (batch seed 123), using the supervisor-provided game dictionary.

| Folder | Contents |
|---|---|
| `batch_100/` | One row per game for each player: starting-grid features, cleared, score, moves, tiles left, branching factor and so on |
| `runtime/` | Time per game for Random and Hybrid (the Greedy files already record runtime) |
| `expert_grids/` | Hybrid run on the 10 grids from the expert human's games, with the words played and the running score |
| `summary.csv` | Per-player averages, generated by `scripts/summarise_results.py` |

## Known quirk in the raw files

In `batch_100/random.csv` and `batch_100/hybrid.csv`, the column labelled **`scoreNoBonus` already includes the +500 clear bonus**. The batch runner that wrote those files stored the game's total score in that column. The Greedy files are labelled correctly and have a separate `total_score_with_bonus` column.

`scripts/summarise_results.py` corrects for this. `summary.csv` and the README report both versions correctly:

| Player | Clear rate | Mean score (with bonus) | Mean score (words only) |
|---|---:|---:|---:|
| Hybrid | 87% | 2,391 | 1,956 |
| Greedy-3 | 10% | 2,132 | 2,082 |

The raw files are left exactly as they were produced. The refactored batch runner (`wordsoup batch`) writes `scoreNoBonus` and `scoreWithBonus` as separate columns.
